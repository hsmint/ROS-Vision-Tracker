# 1부. 문제 정의와 시스템 구성

## 파란 큐브를 스스로 따라보는 CCTV형 2축 카메라

**과제 정의**

- **RealSense D435**가 본 파란 큐브를 화면 중앙으로 끌어오는 것이 목표
- 목표물은 **30×30×60 mm** 파란 직육면체 하나 — 거리 **0.2~1.0 m**에서 찾아야 한다
- 조명은 어두움 · 보통 · 밝음 세 조건 모두에서 같은 설정으로 동작해야 한다
- 비슷한 색의 다른 물체(의자 · 카펫 · 파란 브래킷)를 목표로 오인하면 안 된다
- 사람이 큐브를 들고 움직이거나 손에 반쯤 가려져도 계속 따라가야 한다

## 지켜야 했던 다섯 가지 설계 기준

- **최신성** — 늦게 도착한 프레임보다 다음 프레임이 낫다.
- **일정 주기** — 영상이 끊겨도 명령 타이머는 20 Hz로 계속 0을 내보낸다
- **안전 우선** — 어느 단계가 끊겨도 모터는 반드시 선다.
- **재현성** — 튜닝 값은 코드가 아니라 YAML에 둔다. 재빌드 없이 바꾼다
- **원격 분리** — 네트워크가 느려도 추적 주기는 영향을 받지 않는다

# 2부. 인지와 제어

## 검출은 다섯 단계를 순서대로 통과한다

| 단계 | 검사 | 기준 |
| :---: | :--- | :--- |
| ① | 색 마스크 | HSV + 최소 채도 |
| ② | 면적 | 픽셀 하한 · 상한 |
| ③ | 모양 | 장단비 · 채움비 |
| ④ | 상자 판정 | box_fit 다각형 근사 |
| ⑤ | 뎁스 검증 | 거리 · 실제 크기 |

## 뎁스로 픽셀을 센티미터로 바꾼다

**뎁스 검증**

- 컨투어 안 뎁스의 중앙값 Z를 쓴다 — 경계 화소는 1회 침식으로 제외한다
- 핀홀 모형: `실제 길이 = 픽셀 길이 × Z / f`. 회전에 무관하게 외접사각형 변을 쓴다
- 기준은 짧은 변 ≤ 6 cm, 긴 변 ≤ 8 cm, 실제 넓이 3~30 cm², 거리 0.1~1.1 m
- 초점거리는 `camera_info`가 오면 실제 값으로 바꾸고 면적 기준을 다시 계산한다
- 너무 가까워 뎁스가 없으면 800 px 이상일 때만 색과 크기만으로 통과시킨다

## 제어 — 오차 하나를 각속도로 바꾼다

**`tracker_node` / 추종 제어**

- `명령 = clamp(sign × Kp × 정규화 오차, ±max)` — P 제어 하나로 끝낸다
- |오차| < 데드밴드 0.05면 0 — 중앙 근처에서 좌우로 떠는 것을 막는다
- 팬은 `angular.z`, 틸트는 `angular.y`. 나머지 성분은 항상 0이다
- REP-103을 따른다 — `angular.z` + = 왼쪽, `angular.y` + = 아래
- 각도가 아니라 각속도다 — 모터 드라이버가 위치로 적분하지 않는다

## control_lite — 100 Hz로 시리얼을 지킨다

**`xmen_control` / `control_lite`**

- `/cmd_vel`을 받아 `'v 팬 틸트'` 한 줄을 보내고, `'p'`로 현재 위치를 되묻는다
- 10 ms 주기 타이머가 수신 버퍼를 읽어 줄 단위로 끊고 해석한다
- 받은 엔코더 틱을 라디안으로 바꿔 `/joint_states`에 pan · tilt로 발행한다
- 0.2 s 동안 새 명령이 없으면 0을 보낸다 — 지난 Twist는 절대 재사용하지 않는다
- 포트는 exclusive로 연다 — 다른 프로세스가 같은 포트를 잡지 못하게 한다

## 시작할 때 반드시 원점을 잡고 들어간다

**`control_lite` / 홈 시퀀스**

- 틸트를 먼저, 그다음 팬 — 두 축을 동시에 움직이지 않는다
- 4틱 이내까지 접근한 뒤, 8틱 밴드 안에서 0.2 s 머물러야 도착으로 본다
- 좁은 밴드로 들어가 넓은 밴드로 판정해 경계에서 떠는 것을 막는다
- 한 축을 맞추는 사이 다른 축이 8틱 밖으로 밀리면 최대 3번까지 다시 한다
- 30초 안에 못 맞추면 시작 · 최근접 위치와 마지막 명령을 남기고 멈춘다

# 3부. 결과와 배운 점

## 끊기는 지점마다 정지 규칙을 뒀다

| # | 구간 | 조건 | 동작 |
| :---: | :--- | :--- | :--- |
| 1 | 카메라 → 검출 | 0.5 s 영상 없음 | `CAMERA_STALL` |
| 2 | 검출 → 제어 | 0.5 s 입력 없음 | 두 축 0 발행 |
| 3 | 제어 → 모터 | 0.2 s 명령 없음 | `'v 0 0'` 전송 |
| 4 | Pi → OpenCR | 모터 워치독 200 ms | 모터 자체 정지 |
| 5 | 노드 종료 | 종료 직전 0 발행 | shutdown 처리 |

## 원격 PC로 원본 영상을 보내지 않는다

**`preview_node`**

- 640×360 컬러 30 Hz 원본은 초당 약 21 MB — 흘리면 추적까지 같이 느려진다
- Pi에서 박스를 그린 뒤 JPEG 품질 70으로 5 Hz만 내보낸다
- 구독자가 하나도 없으면 인코딩 자체를 하지 않는다
- 영상과 박스는 타임스탬프가 정확히 맞는 짝만 보낸다 — 옛 박스를 덧그리지 않는다
- 원본 RGB · 뎁스는 Pi 안에 남고, 검출 · 명령은 20 Hz 그대로다

## RViz2에서 로봇과 목표를 함께 본다

**`xmen_description` / `rviz_node`**

- Onshape에서 뽑은 URDF와 STL로 CCTV 본체를 RobotModel로 띄운다
- `camera_link`는 CAD 카메라 하우징 +Y 면에 붙어 팬 · 틸트를 따라 움직인다
- 주석이 그려진 영상을 `camera_link` 앞 0.25 m에 폭 0.4 m 평면으로 세운다
- 목표 마커는 `tracking_image` 프레임에 고정돼 카메라와 함께 돈다
- 이건 표시용 좌표계다 — 실제 작업 공간의 측정 위치가 아니다

## 튜닝과 평가를 명령 하나로 돌린다

**`target_perception` / tuning · evaluate**

- **tune** — 화면에서 드래그하면 그 화소로 HSV 범위를 제안하고 트랙바로 다듬는다
- **collect** — 조명 · 거리 라벨을 붙여 컬러 + 뎁스를 30장씩 데이터셋으로 모은다
- **bench** — 조건별 100프레임의 검출률 · Z · 처리 시간을 측정한다
- **evaluate** — 저장된 뎁스로 노드와 같은 검증까지 돌려 설정 A · B를 비교한다
- 결과는 조명×거리 인식률 표와 조건별 몽타주 이미지로 남는다
