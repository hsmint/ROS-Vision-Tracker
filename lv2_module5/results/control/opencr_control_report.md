# opencr_control.ino 코드 설명 보고서

date: 2026-10-03

Pi: pa06

## 개요

opencr_control.ino(493줄, 버전 `OPENCR_CONTROL_V2`)는 OpenCR 보드에서 도는 펌웨어입니다. 라즈베리파이의 main.py가 보낸 글자 명령을 해석해 다이나믹셀 모터 두 대(XM430-W350)를 움직입니다.

| 축 | 모터 ID | 홈 위치(엔코더 틱) | 허용 범위 |
|---|---|---|---|
| X축(좌우, pan) | 11 | 0 | 홈 기준 ±180° |
| Y축(상하, tilt) | 12 | 2048 | 홈 기준 ±135° |

코드 안에서는 배열 순서가 **Y축이 0번, X축이 1번**입니다. 사용자가 입력하는 순서(X 먼저)와 반대라서 읽을 때 주의해야 합니다. 모터 한 바퀴는 4096틱이고, 1°는 약 11.4틱입니다.

아두이노 스케치라서 `setup()`은 전원을 켤 때 한 번, `loop()`는 그 뒤로 계속 반복합니다. 나머지 함수는 모두 이 두 함수가 부르는 부품입니다. C++에서는 함수 안에 함수를 만들 수 없어서, 부품 함수들은 `loop()` 밖에 정의되어 있습니다.

사용자 명령은 모두 `loop()` → `command()`를 거쳐 들어오고, 모터를 실제로 다루는 일은 아래의 공통 부품이 맡습니다.

## 42~65줄: 기본 보조 함수

다른 함수들이 공통으로 쓰는 작은 계산·읽기 함수입니다.

| 줄 | 함수 | 하는 일 |
|---|---|---|
| 43~46 | `readValue(id, item, value)` | 모터의 항목(위치, 토크 등) 하나를 읽어 `value`에 넣습니다. 통신 오류·모터 오류가 없을 때만 `true`입니다. 최대 30ms 기다립니다. |
| 48~53 | `nearestError(position, home)` | 현재 위치에서 가장 가까운 홈까지의 차이(틱)를 구합니다. 한 바퀴(4096틱) 경계를 넘는 경우도 고려해 -2048~+2048 사이로 돌려줍니다. |
| 54 | `limitTicks(i)` | 허용 각도를 틱으로 바꿉니다. X축 180° = 2048틱, Y축 135° = 1536틱입니다. |
| 55 | `ticksToDeg(ticks)` | 틱을 각도(°)로 바꿉니다. 틱 × 360 ÷ 4096입니다. |
| 56~58 | `positionCheck(s)` | 저장 위치의 검사값을 계산합니다. 저장 중 전원이 꺼져 값이 깨졌는지 알아내는 데 씁니다. |
| 60~65 | `loadPosition()` | EEPROM에서 마지막 위치를 읽습니다. 확인용 번호·검사값이 맞고 허용 범위 안일 때만 `saved_valid`를 `true`로 둡니다. |

`nearestError()`의 한계도 있습니다. 모터는 전원을 켤 때 몇 바퀴 돌았는지 기억하지 못해서, 케이블이 한 바퀴 더 감겼는지는 이 함수만으로 알 수 없습니다. 그래서 V2부터는 저장 위치를 함께 써서 판단합니다(`prepareAxis` 참고).

## 66~104줄: 안전 함수

정지, 위치 저장, 오류 처리를 담당합니다. 여러 곳에서 불리므로 한 곳에 모아 두었습니다.

### hold() (67~83줄): 그 자리에 멈추기
1. 이동 중 표시(`active`, `sequence`, `dual_move`)를 모두 끕니다.
2. 준비된 축마다 토크가 켜져 있는지 읽습니다. 못 읽으면 경고를 출력합니다.
3. 토크가 켜진 축은 현재 위치를 새 목표로 쓰고, `targets`도 그 위치로 바꿉니다.
4. 목표를 못 쓰면 토크를 끄고 “카메라를 받치라”는 경고를 출력합니다.
5. 모두 성공하면 `true`를 돌려줍니다.

### savePosition() (85~97줄): 마지막 위치 저장
1. 두 축이 모두 준비된 상태가 아니면 저장하지 않습니다.
2. 두 축의 홈 기준 위치(`targets - anchors`)와 검사값을 만듭니다.
3. 이미 저장된 값과 같으면 쓰지 않습니다. EEPROM 수명을 아끼기 위해서입니다.
4. EEPROM에 쓴 뒤 다시 읽어 똑같은지 확인합니다. 다르면 `WARNING: position save failed.`를 출력합니다.
5. 성공하면 `SAVED: X=... Y=... deg from home.`를 출력합니다.

### require() (98~104줄): 성공 여부 검사

모터 명령을 보낼 때마다 `require(명령, "원인")` 형태로 감싸서 씁니다. 명령이 실패하면 세 가지를 합니다.
- 원인을 `reason`에 저장하고 `faulted`를 `true`로 둡니다.
- `hold()`로 정지를 시도합니다.
- `FAULT: 원인`을 출력합니다.

`faulted`는 다시 `false`로 돌아가지 않습니다. FAULT 상태에서는 새 이동을 모두 거부하므로, 원인을 해결한 뒤 보드를 재시작해야 합니다.

## 106~131줄: printStatus(), 상태 출력

`p` 명령을 받으면 보드와 모터 상태를 한눈에 볼 수 있게 출력합니다. 설정을 바꾸지는 않습니다.

| 출력 줄 | 내용 |
|---|---|
| `FIRMWARE=` | 펌웨어 버전(`OPENCR_CONTROL_V2`) |
| `STATE=` | `FAULT`, `MOVING`, `IDLE` 중 하나와 오류 원인, 복귀 속도, 자동 홈 설정 |
| `SAVED_POSITION=` | 저장된 마지막 위치. 없으면 `none` |
| `tilt ID12 ...` / `pan ID11 ...` | 축별 엔코더 값(`ticks`), 홈 기준 각도(`home_deg`), 토크, 하드웨어 오류, 속도 상한 |

축 정보를 하나라도 못 읽으면 그 축은 `READ_ERROR`로 표시합니다. 축을 아직 준비하지 않았으면 `home_deg`는 가장 가까운 홈을 기준으로 계산한 값입니다.

## 132~167줄: prepareAxis(), 축 준비

모터를 움직이기 전에 항상 거치는 점검 단계입니다. 모터가 정상인지 확인하고, 홈 기준점(`anchors`)과 이동 기준점(`targets`)을 정합니다.
1. **연결·모델 확인 (135~136줄):** ping에 응답하는지, 모델이 XM430-W350인지 확인합니다.
2. **설정 점검 (137~142줄):** 토크 상태를 읽고, Homing Offset이 0인지, 하드웨어 오류가 없는지, 속도 기반 프로파일인지 확인합니다.
3. **모드 설정 (143~147줄):** 확장 위치 모드(Extended Position)가 아니면 토크를 끄고 모드를 바꿉니다. 이 모드는 여러 바퀴 회전을 셀 수 있습니다.
4. **현재 위치 읽기 (148줄)**
5. **이동 기준 결정 (150줄):** 토크를 유지 중이면 마지막 목표를 그대로 기준으로 씁니다. 그래야 여러 번 상대 이동해도 오차가 쌓이지 않습니다. 토크가 꺼져 있으면 현재 위치가 기준입니다.
6. **홈 기준점 계산 (151~160줄, 처음 준비할 때만):**
   - 현재 위치에서 가장 가까운 홈을 고릅니다.
   - 저장 위치가 있으면, 그 위치와 가장 가까운 바퀴를 고릅니다. X축이 ±180° 근처에 있을 때 어느 쪽으로 돌았는지 판단하기 위해서입니다.
   - 홈 기준 위치가 허용 범위를 벗어나면 `REJECTED`를 출력하고 멈춥니다. FAULT는 아닙니다.
7. **마무리 (161~166줄):** 통신 감시 타이머를 끄고, 가속도를 가장 완만한 값(1)으로 두고, 목표를 기준 위치로 씁니다. 그래서 토크를 켜도 모터가 튀지 않습니다.

점검 중 하나라도 실패하면 `require()`가 FAULT를 걸고 `false`를 돌려줍니다.

## 168~195줄: moveAxis()와 readyForMove()

### moveAxis(i, rel, speed) (169~189줄): 한 축만 이동

홈 복귀와 위치 복원에서 축을 하나씩 움직일 때 씁니다. `rel`은 홈 기준 목표 위치(틱), `speed`는 속도(°/s)입니다.

| 줄 | 하는 일 |
|---|---|
| 172~173 | 현재 위치와 모터에 설정된 속도 상한(Velocity Limit)을 읽습니다. |
| 174~175 | 속도를 모터 단위(1 = 1.374°/s)로 바꿉니다. 30°/s는 21(실제 약 28.9°/s)입니다. 상한을 넘으면 거부합니다. |
| 176~177 | 목표 틱 = 홈 기준점 + `rel`입니다. 모터가 표현할 수 있는 범위인지 확인합니다. |
| 178 | 이동 속도를 모터에 씁니다. |
| 179~180 | 목표를 현재 위치로 먼저 쓰고 토크를 켭니다. 토크를 켜는 순간 튀지 않게 하려는 순서입니다. |
| 181 | 통신 감시 타이머를 25(500ms)로 켭니다. 보드가 500ms 동안 모터와 통신하지 않으면 모터가 스스로 멈춥니다. |
| 182 | 실제 목표를 씁니다. 여기서 모터가 움직이기 시작합니다. |
| 183~187 | 목표와 시작 시각을 기억하고 `MOVING tilt ... deg from home at ... deg/s.`를 출력합니다. |

도착 판정은 이 함수가 아니라 `loop()`가 합니다. 그래서 함수는 명령만 보내고 바로 끝납니다.

### readyForMove() (191~195줄): 이동 가능 여부

새 이동 명령을 받기 전에 확인합니다. FAULT 상태면 `FAULT: 원인`, 이미 움직이는 중이면 `BUSY: send x to stop first.`를 출력하고 거부합니다.

## 196~231줄: 입력 해석

`5 -5 3` 같은 글자열을 숫자 세 개로 바꾸고, 쓸 수 있는 값인지 검사합니다.

### readDecimal() (197~216줄): 숫자 하나 읽기
1. 앞의 공백을 건너뜁니다.
2. `+` 또는 `-` 부호가 있으면 기억합니다.
3. 정수 부분을 한 자리씩 읽습니다. 1,000,000을 넘으면 잘못된 입력으로 봅니다.
4. `.`이 있으면 소수 부분을 읽습니다.
5. 숫자가 하나도 없거나, 숫자 뒤에 공백이 아닌 글자(예: `5a`)가 붙어 있으면 실패입니다.

`text`는 참조(`&`)로 받기 때문에, 읽은 만큼 앞으로 이동한 상태로 돌아갑니다. 그래서 연달아 부르면 다음 숫자를 읽습니다. 동적 메모리를 쓰지 않아 마이크로컨트롤러에서 안전합니다.

### parseCommonMove() (220~231줄): 이동 명령 해석

| 줄 | 하는 일 |
|---|---|
| 222~224 | `readDecimal()`을 세 번 불러 X 변화량, Y 변화량, 속도를 읽습니다. |
| 225~227 | 뒤에 다른 글자가 남아 있거나, X가 ±360°·Y가 ±270°를 넘거나, 속도가 1.374°/s 미만이면 거부합니다. |
| 228~229 | 결과를 `values`에 담습니다. 속도는 두 축에 같은 값을 넣습니다. |

여기서는 변화량만 검사합니다. 이동 후 위치가 홈 기준 범위 안인지는 현재 위치를 알아야 하므로 `moveBoth()`에서 검사합니다.

## 233~304줄: moveBoth(), 두 축 상대 이동

`5 -5 3` 명령을 실제 이동으로 바꾸는 핵심 함수입니다. 두 모터에 목표를 한 번에(Sync Write) 보내 동시에 출발시킵니다.

| 줄 | 단계 | 하는 일 |
|---|---|---|
| 236 | 이동 가능 확인 | `readyForMove()`로 FAULT·이동 중이면 거부합니다. |
| 237~238 | 순서 바꾸기 | 입력(X, Y)을 내부 순서(Y, X)로 바꿉니다. |
| 240~250 | 속도 검사 | 각 모터의 속도 상한을 읽고, 입력 속도를 모터 단위로 바꾼 뒤 상한을 넘으면 거부합니다. |
| 251~256 | 가속도 계산 | 약 0.3초 만에 설정 속도에 도달하도록 가속도를 정합니다. 모터 단위 1 = 21.4577°/s²입니다. |
| 257 | 축 준비 | `prepareAxis()`를 두 축에 부릅니다. |
| 258~271 | 목표 계산과 범위 검사 | 목표 = 현재 목표(`targets`) + 변화량입니다. 홈 기준 범위를 벗어나면 `REJECTED: X result ... outside +/-180; current ...`를 출력하고 멈춥니다. |
| 273~276 | 토크 켜기 | 두 모터의 토크와 통신 감시 타이머(500ms)를 켭니다. 목표가 아직 현재 위치라 움직이지 않습니다. |
| 277~286 | 패킷 만들기 | 모터마다 가속도·속도·목표 위치 12바이트를 묶습니다. 모터 제어표 108번 주소부터 연속으로 씁니다. |
| 287 | 동시 전송 | Sync Write 패킷 하나로 두 모터에 보냅니다. 이 순간 두 축이 함께 출발합니다. |
| 288~295 | 적용 확인 | Sync Write는 응답이 없어서, 각 모터의 목표를 다시 읽어 맞는지 확인합니다. |
| 296~303 | 상태 기록과 출력 | 두 축 이동 중으로 표시하고 `MOVING XY: dX=... dY=... -> X=... Y=... deg from home; ...`를 출력합니다. |

이 함수도 도착을 기다리지 않고 바로 끝납니다. 도착 판정과 위치 저장은 `loop()`가 합니다.

## 306~338줄: 순차 이동(홈 복귀·위치 복원)

홈 복귀와 위치 복원은 둘 다 Y축을 먼저 옮기고, 도착하면 X축을 옮깁니다. 속도는 30°/s(실제 약 28.9°/s)입니다.

| 줄 | 함수 | 하는 일 |
|---|---|---|
| 307~310 | `startSequence(name, rel)` | 이름(HOME/RESTORE)과 두 축 목표를 기억하고, Y축 이동을 시작합니다. X축은 Y축 도착 후 `loop()`가 이어서 움직입니다. |
| 312~317 | `startHome()` | `h` 명령입니다. 이동 가능 여부를 확인하고, 두 축을 준비한 뒤 목표 (0, 0)으로 순차 이동합니다. |
| 319~338 | `startRestore()` | 보드를 켤 때(`auto off`인 경우) 한 번 실행됩니다. 아래 순서를 따릅니다. |

### startRestore()의 판단 순서
1. 저장 위치가 없으면 `RESTORE: no saved position; waiting for commands.`를 출력하고 끝납니다.
2. 두 모터에 ping을 보냅니다. 응답이 없으면 `RESTORE skipped: motor ID.. no response.`를 출력하고 끝납니다. 모터 전원이 아직 없을 때 FAULT가 걸리지 않게 하려는 단계입니다.
3. 두 축을 준비합니다. 이때 저장 위치를 참고해 바퀴를 판단합니다.
4. 현재 위치와 저장 위치의 차이가 두 축 모두 12틱(약 1.05°) 이내인지 비교합니다.
5. 같으면 `POSITION OK: saved X=... Y=...`를 출력하고 그대로 둡니다. 토크도 켜지 않습니다.
6. 다르면 `POSITION CHANGED: now X=... Y=...; saved X=... Y=...`를 출력하고 저장 위치로 순차 이동합니다.

## 339~381줄: 토크 해제와 모터 조회

| 줄 | 함수 | 하는 일 |
|---|---|---|
| 340~350 | `release()` | `off` 명령입니다. 이동을 취소하고, 두 축의 토크와 통신 감시 타이머를 끕니다. 다음 이동 때 홈 기준을 다시 계산하도록 `configured`도 끕니다. 카메라 무게로 축이 내려갈 수 있으므로 먼저 받쳐야 합니다. 위치는 저장하지 않습니다. |
| 352~361 | `scanField(id, item, name)` | 모터 항목 하나를 읽어 `이름=값`으로 출력합니다. 실패하면 라이브러리 오류 번호와 모터 오류 번호를 출력합니다. |
| 363~381 | `scanMotors()` | `scan` 명령입니다. ID 11과 12에 ping을 보내고, 응답하면 모델, 펌웨어, 위치, 속도, Homing Offset, 토크, 하드웨어 오류, 입력 전압을 출력합니다. 설정은 바꾸지 않으며, 이동 중에는 거부합니다. |

`input_voltage_raw_0.1V`는 0.1V 단위입니다. 예를 들어 120이면 12.0V입니다.

## 383~419줄: 정지·저장과 명령 처리

### stopAndSave() (384~388줄)

`x`를 받으면 `hold()`로 멈추고 `STOP: holding current positions.`를 출력합니다. 정지가 성공하고 FAULT가 아니면 그 위치를 저장합니다.

### command(line) (390~419줄): 명령 분기

한 줄짜리 명령을 받아 알맞은 함수로 보냅니다. 앞뒤 공백을 지우고(391~393줄), 빈 줄이면 무시합니다(394줄).

| 줄 | 입력 | 부르는 함수 |
|---|---|---|
| 395 | `h` | `startHome()` |
| 396 | `x` | `stopAndSave()` |
| 397 | `off` | `release()` |
| 398 | `p` | `printStatus()` |
| 399 | `scan` | `scanMotors()` |
| 400~409 | `auto on` / `auto off` | 직접 처리. 설정을 EEPROM 주소 0에 쓰고 다시 읽어 확인합니다. 잘못 저장되면 `ERROR: boot setting verification failed.`입니다. |
| 410~411 | 숫자 세 개 | `parseCommonMove()`가 성공하면 `moveBoth()` |
| 412~418 | 그 밖의 입력 | 숫자로 시작하면 `INVALID XY`와 입력 바이트(16진수)를 출력합니다. 이어서 사용법을 출력합니다. |

`auto` 설정에는 확인용 번호(`BOOT_MAGIC`)와 반대 값(254/255)을 함께 저장합니다. 두 값이 모두 맞아야 켜진 것으로 봐서, 저장 공간이 깨져도 우연히 켜지지 않습니다.

## 420~438줄: setup(), 전원을 켤 때 한 번

| 줄 | 코드 | 뜻 |
|---|---|---|
| 422 | `Serial.begin(115200)` | 라즈베리파이와 USB 통신을 엽니다. main.py의 `BAUDRATE`와 같아야 합니다. |
| 423 | `dxl.begin(1000000)`, 프로토콜 2.0 | 모터와 1 Mbps로 통신을 엽니다. |
| 424~425 | `EEPROM.get(0, setting)` | 자동 홈 설정을 읽습니다. 확인용 번호와 반대 값이 맞을 때만 켭니다. |
| 426 | `loadPosition()` | 마지막 저장 위치를 읽습니다. |
| 427 | `delay(2000)` | 2초 기다립니다. 모터 전원과 USB 연결이 안정될 시간입니다. |
| 428~433 | `parseCommonMove("10 10 10", ...)` | 입력 해석 기능을 스스로 점검합니다. 실패하면 FAULT로 두고 끝납니다. |
| 434~436 | `Serial.print...` | 버전과 `OPENCR_READY` 안내를 출력합니다. |
| 437 | `if (auto_home) startHome(); else startRestore();` | `auto on`이면 홈 복귀, 아니면 저장 위치와 비교해 필요하면 복원합니다. |

`setup()`은 이동을 **시작만** 합니다. 도착까지 기다리는 일은 `loop()`가 맡아서, 복원 중에도 `x`로 바로 멈출 수 있습니다.

## 439~493줄: loop(), 계속 반복

한 번 돌 때마다 세 단계를 거칩니다. 입력 처리는 매번 하고, 모터 점검은 100ms마다 한 번만 합니다.

### 1단계: 시리얼 입력 모으기 (441~451줄)
- **441줄:** `static` 변수는 `loop()`가 끝나도 값이 유지됩니다. `line`은 최대 79글자까지 모으는 명령 상자, `used`는 모인 글자 수, `overflow`는 너무 길었는지 여부입니다.
- **442줄:** 한 번에 최대 32글자만 읽습니다. 입력이 많아도 모터 점검이 밀리지 않게 하려는 제한입니다.
- **444줄:** `x` 글자는 줄바꿈을 기다리지 않고 **받자마자** 멈춥니다. 비상 정지를 빠르게 하려는 설계입니다.
- **445~448줄:** 줄바꿈이 오면 모인 글자를 `command()`로 넘깁니다. 너무 길면 `Command too long; discarded.`입니다.
- **449줄:** 백스페이스면 한 글자를 지웁니다.
- **450줄:** 나머지 글자는 상자에 넣습니다.

### 2단계: 100ms마다 오류 점검 (452~460줄)
- **452~453줄:** 마지막 점검 후 100ms가 지나지 않았으면 여기서 끝납니다.
- **454~459줄:** 준비된 축의 하드웨어 오류를 읽습니다. 통신 실패나 오류가 있으면 FAULT입니다. 이 주기적인 통신이 모터의 통신 감시 타이머(500ms)도 매번 초기화합니다.
- **460줄:** 이동 중이 아니면 여기서 끝납니다.

### 3단계: 도착 판정

**두 축 동시 이동일 때 (461~477줄)**
- 제한 시간 = 15초 + (허용 범위의 2배 ÷ 속도)입니다. 넘으면 `dual movement timeout` FAULT입니다.
- 목표와 8틱(약 0.7°) 이내이고 거의 멈춰 있으면 “도착”으로 셈니다.
- 이 판정이 **5번 연속(약 0.5초)** 나오면 확실히 도착한 것으로 봅니다. 잠깐 지나치는 순간을 도착으로 오해하지 않기 위해서입니다.
- 두 축 모두 도착하면 `DONE XY: both axes reached; holding position.`를 출력하고 위치를 저장합니다.

**순차 이동(홈·복원)일 때 (478~492줄)**
- 제한 시간과 도착 기준은 위와 같고, 지금 움직이는 축(`stage`) 하나만 봅니다.
- 도착하면 `REACHED tilt` 또는 `REACHED pan`을 출력합니다.
- Y축(tilt)이 도착했고 순차 이동 중이면 X축 이동을 시작합니다(487줄).
- X축까지 도착하면 `DONE HOME` 또는 `DONE RESTORE`를 출력하고 위치를 저장합니다.

도착 후에도 토크는 자동으로 끄지 않습니다. 카메라가 무게로 처지지 않게 위치를 계속 잡고 있습니다.

## 출력 메시지 요약

main.py 화면에 나타나는 보드 메시지와, 그 메시지를 내는 함수입니다.

| 메시지 | 나오는 곳 | 뜻 |
|---|---|---|
| `OPENCR_READY` | `setup()` | 부팅 완료, 명령 받을 준비가 됨 |
| `POSITION OK` | `startRestore()` | 저장 위치와 같아서 움직이지 않음 |
| `POSITION CHANGED` | `startRestore()` | 저장 위치와 달라서 복원 시작 |
| `RESTORE skipped` | `startRestore()` | 모터 응답이 없어 복원을 건너뜀 |
| `MOVING XY` | `moveBoth()` | 두 축 상대 이동 시작 |
| `MOVING tilt` / `MOVING pan` | `moveAxis()` | 홈·복원 중 한 축 이동 시작 |
| `REACHED tilt` / `REACHED pan` | `loop()` | 한 축 도착 |
| `DONE XY` / `DONE HOME` / `DONE RESTORE` | `loop()` | 이동 완료, 위치 유지 |
| `SAVED` | `savePosition()` | EEPROM에 위치 저장 |
| `STOP` | `stopAndSave()` | 정지 후 위치 유지 |
| `OFF` | `release()` | 토크 해제, 카메라를 받쳐야 함 |
| `BUSY` | `readyForMove()`, `scanMotors()` | 이동 중이라 거부. 먼저 `x` |
| `REJECTED` | `moveBoth()`, `moveAxis()`, `prepareAxis()` | 범위·속도 초과로 거부. FAULT는 아님 |
| `INVALID XY` | `command()` | 숫자 명령 형식이 틀림 |
| `FAULT` | `require()` | 모터 통신·하드웨어 오류. 보드 재시작 필요 |
| `WARNING` | `hold()`, `savePosition()` | 정지 또는 저장 실패 |
